# HDTools 0.2.0

通过唯一的 485 通道浏览设备文件、上传下载、执行命令的桌面应用。界面参考 CamDock
“设备文件”，连接使用 H485 维护协议；macOS / Windows 使用同一套 Compose Desktop 界面。

xpl 于 2026-11-20 确认本轮验证完毕；双板交互终端及读模式取消测试见
[VALIDATION.md](../VALIDATION.md)。

## 启动

Mac 已构建的应用位于 `build/compose/binaries/main/app/HDTools.app`，安装包位于
`build/compose/binaries/main/dmg/HDTools-1.2.0.dmg`。应用版本为 0.2.0；Mac 安装包因
Compose/macOS 主版本必须大于零，采用 1.2.0 映射。

也可以用 JDK 17 从本目录运行：

```sh
./gradlew run
./gradlew run --args=--demo
```

Windows 使用 `gradlew.bat run`。Windows EXE 须在 Windows 的 JDK 17 / WiX 环境构建：

```bat
gradlew.bat test packageExe
```

协议集成测试需要 Python 3、POSIX PTY 与已构建的板端服务；Windows 上跳过
真实服务的 PTY 联调测试，仍运行帧解析、重试等平台无关测试。Windows 安装、UI、真实 COM
口尚待 Windows 主机验收；不把 Mac 打包结果作为 Windows 验收。

## RV1106 准备

文件浏览需要 `hd485d 0.2.0+`，终端保持工作目录需要 **0.2.1+**；原板端 0.1.1 可继续执行终端命令，但不支持文件浏览。
先核验串口占用并正常停止旧 hd485d，然后在新版包的 `rv1106/` 目录执行：

```sh
sh tools/run-rv1106.sh --allow-shell --fs-root /
```

方式一为默认模式：业务申请串口后维护会话失效，释放后可重新连接。该命令不修改
开机脚本。`--fs-root /` 显式允许服务进程在整个文件系统范围访问文件；也可设置为
一个已存在的目录，界面 `/` 即映射到该目录。原 Python CLI 的 `--root` 相对路径传输
仍使用 `/userdata/hd-rs485/files`，两者独立。

使用当前温控器链路时，主机选择 `/dev/cu.usbserial-FTAP6OK03`、230400、地址 1，
8N1、无流控；不要选日志口 `/dev/cu.wchusbserial144440`。关闭 CamDock 或其他
工具对同一 485 串口的连接后再连接 HDTools。

## 使用

- 连接后自动从 `/` 浏览。输入路径前往、双击目录、返回上级、刷新；名称筛选只影响当前列表。
- 显示隐藏文件、权限、大小、修改时间和链接目标。符号链接及特殊文件只显示，不跟随传输。
- 上传单个普通文件到当前目录；目标存在时确认覆盖，完成校验后替换。文件上限 64 MiB。
- 选择普通文件后下载，选择本地保存路径；保留目标原文件直到 SHA-256 校验成功。
- 点击取消后保留文件断点。重新选择相同本地文件和设备路径，显式发起上传／下载即可恢复。
  上传身份由路径、大小、SHA-256 确定；下载在目标旁保存 `.hdtools.part` 和 `.hdtools.meta`，
  仅匹配路径、大小、哈希的断点可恢复。身份不符时另选位置或手动移走旧断点。
- 中断上传的板端临时文件是目标目录内 `.hd485-*.part/.meta`；文件列表隐藏它们。
  不同内容上传同一名字可能提示断点冲突；通过终端 `ls -a` 核对后，由操作者决定清理。
- 终端输入 `@version`、`ls -al /userdata`、`cat /proc/version` 等命令，点击执行。
  取消按钮发送 CANCEL，显示输出与退出码。此命令执行视图不支持交互输入；vi/top 请使用新版交互终端；
  连接 0.2.1+ 时，同一连接内 `cd` 会改变下一条命令的工作目录，支持 `cd -`；
  文件浏览路径独立。重连重置目录；环境变量、alias 和函数仍不跨命令保留。
- 输出仅保留当前窗口最近 256 Ki 字符，可搜索、复制、自动跟随、清空、导出 UTF-8 日志。
  板端每个输出流最多 128 KiB；发生截断会明确显示。命令默认 30 秒超时。
- 无应答不能确定是业务占用、断线还是参数不符。不会自动建立新会话重做命令。
  重新连接后先核对命令或文件结果，再选择是否恢复操作。

虚拟文件系统的动态内容（例如 `/proc` 中显示大小为零的文件）应通过终端 `cat`
读取，不使用普通文件快照下载。文件操作不依赖设备安装 stat、base64 或 sha256sum。

默认只记忆串口、速率、地址，不自动连接、不自动记录命令和日志。配置在
`~/Documents/tmp/hd-rs485-drive/HDTools/connection.properties`；可用 JVM 参数
`-Dhdtools.data=/指定目录` 改变位置。演示模式不打开真实串口、不保存连接配置。

## 构建和验证

沿用参考项目已有的 Kotlin 2.2.21、Compose 1.9.3、Gradle 8.13、jSerialComm 2.11.2。

```sh
# 在仓库根目录先构建测试服务
cmake -S . -B build -DHD485_SANITIZE=ON
cmake --build build --parallel 4
python3 tests/integration.py
# 然后进入 HDTools
cd HDTools
./gradlew test
./gradlew createDistributable packageDmg
./gradlew run --args='--screenshot ../build/hdtools-preview.png'
```

`test` 中的 TCP 仅用作测试 PTY 桥，另一端运行实际 hd485d；产品连接只使用串口。
测试临时文件统一保留在 `~/Documents/tmp/hd-rs485-drive/hdtools-tests/`，报告在
`build/reports/tests/test/`。本次完成程度及限制见仓库 `VALIDATION.md`。

0.1.1：根据 RV1106 实测，在每次有效应答后至少等待 60 ms 再发送下一请求，
避免 UART 排空／GPIO 换向尚未完成时丢失下一帧。板端协议与服务 0.2.0 保持不变。


## 串口读写状态（0.1.2）

连接栏下方显示当前模式：未连接、空闲、写模式（发送）、读模式（等待应答）、换向等待。
每个 H485 请求发送完成后自动进入读模式，并显示剩余等待时间与当前尝试次数。
只有收到当前操作码／地址／会话／请求编号匹配且 CRC 正确的完整应答才正常退出；
分片、噪声或其他请求的应答不会提前解除读模式。界面与会话层均阻止额外请求写入。

- 收到完整应答：自动退出读模式，继续当前任务；下一请求仍遵循 60 ms 换向间隔。
- 读取超时：先退出读模式，再按原有策略重发同一请求，最多发送 3 次。
  全部超时后断开连接并提示检查；不会保持在读模式，也不会新建会话重做命令。
- **取消读取**：只在等待应答时可用，立即结束本次等待并停止整个当前任务，不重试，
  不自动发送文件关闭或取消命令。串口保持连接，等待用户显式发起下一操作；已取消请求
  的迟到应答不能作为下一请求的结果。若连接尚未完成，则释放串口，需重新连接。
- 取消读取不等于取消设备上已经启动的命令，设备执行结果可能未知；请先核对结果。
  **取消任务**仍保留原功能：在安全请求边界发送命令 CANCEL 或停止文件传输。

上述 0.1.2 读写状态功能只涉及 HDTools；下述目录保持功能需要升级板端。


## cd 与会话目录（0.1.3 / hd485d 0.2.1）

升级板端至 0.2.1 后，连接栏的终端提示显示“工作目录随会话保留”。在同一连接中依次执行：

```sh
cd /userdata
pwd
```

第二条输出 `/userdata`。支持相对目录和 `cd -`。设备目录列表不会随 Shell 的 cd 自动跳转。
取消或超时终止命令不更新目录；取消本地读取不等于取消板端命令，结果未知时应先用 pwd 核对。
旧版服务会显示“独立命令 · 不保留目录”，不会把新功能错误地宣称为可用。

## 0.2.0 交互终端

板端 hd485d 0.3.0 使用 `--allow-shell --allow-pty --mode idle` 启动后，连接栏可打开
“交互终端”。该视图支持 vi、top、Tab、方向键、Esc、Ctrl+C/D、复制粘贴和窗口尺寸同步。
使用 JediTerm 3.72，通过 Compose SwingPanel 显示；实际键盘数据仍走 H485 轮询协议，
不连接 SSH、不启动主机 Shell。保留“命令执行”作为旧板端及非交互操作入口。

等待应答时按键在本地排队，物理串口禁止写；输入队列上限 4 KiB，大段粘贴需分段。
交互期间暂停文件和普通命令操作。关闭按钮结束板端 Shell；重新打开创建新会话。
“取消读取”停止当前等待和所有后续自动写，结果未知，板端默认 20 秒无请求后回收。
业务抢占同样结束交互会话，未保存的 vi 内容可能丢失；不自动恢复或重新执行。

Mac 包 `HDTools-1.2.0.dmg`；Windows 未实机验收。板卡、资源与部署见
[BOARD_PTY.md](../BOARD_PTY.md)。JediTerm 第三方声明见 THIRD_PARTY.md。
